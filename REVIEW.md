# Review

- [fixed] correctness: an HTTP 403 on a submission POST was treated as fatal bad credentials (src/push.rs:146). The whole push stopped at the first submission of a form the App User can't access, and the output said to "run the same command again", which would fail the same way. -> A 403 on POST is now a per-submission `rejected` result and the upload continues. 401 is still fatal, and a 403 at preflight is still a credentials error. Test: `push_continues_past_form_the_app_user_cannot_access`.
- [fixed] correctness: when the same phone was copied twice (once while a form was a draft, again after it was finalized), the two copies were reported as a CONFLICT and the finalized submission was never sent (src/instance.rs:414). -> In `dedupe`, draft copies are set aside as older copies whenever a non-draft copy of the same instanceID exists. Real conflicts between non-draft copies are still reported. Test: `draft_then_finalized_copy_of_same_phone_is_not_a_conflict`.
- [fixed] correctness: `push` returned exit 0 even when some submission folders could not be read, which contradicts the documented exit code 1 for "unreadable submissions" (src/lib.rs:348, src/lib.rs:411). -> Scan problems now make the exit code 1. Test: `push_exit_code_flags_unreadable_submissions`.
- [fixed] correctness: `csv` always returned 0, even with conflicts (left out of the export) or unreadable submissions (src/lib.rs:442). -> It now returns 1 in those cases, as documented. Test: `csv_exit_code_flags_conflicts_and_unreadable`.
- [fixed] correctness: batch splitting ignored multipart headers (src/push.rs:162), so a request planned to fit exactly under `X-OpenRosa-Accept-Content-Length` could go over it. -> 256 bytes of overhead is now counted per part, plus the XML part and the closing part. Test: `batches_count_multipart_overhead`. The existing `batches_respect_limit` test was adjusted to match.
- [fixed] correctness: a whitespace-only `<instanceID>` was parsed as `Some("")` (src/instance.rs:116), so all such submissions would be grouped as one instanceID and flagged as conflicts. -> Blank IDs are now treated as no ID. Test: `blank_instance_id_is_none`.
- [fixed] correctness: the HTTP client had a 600 s global timeout per request (src/push.rs:65). With Central's 100 MB limit, a batch on a slow field link (for example 1 Mbit/s) needs more than 600 s, so it would fail on every retry and never upload. -> The global deadline is replaced by a 60 s connect timeout and a 600 s wait for the response. There is no regression test: reproducing it needs a transfer longer than 10 minutes, which is not reasonable in the test suite.
- [fixed] honesty: README told users to "Download a release binary" from a releases page that has no releases and no release workflow (README.md:42). -> It now says there are no prebuilt binaries yet and gives the `cargo install --git` build path (URL matches `$FORGE_REPO_BASE`).
- [fixed] honesty: README said `scan` "lists identical copies", but it only prints a count. -> The wording now says it counts them. README also now documents the draft-copy rule and the 403-continues behavior.
- [unfixed] correctness (minor): rejection messages that contain line breaks are written as multi-line quoted CSV fields in the push log, and the line-based log reader does not rejoin them. Only `created` rows matter for resuming, and those never have a message, so resume is unaffected. Left alone to keep changes minimal.
- [unfixed] harm (by design, documented): submissions with unknown status (no `instances.db` copied) are pushed by default, with a warning, so drafts may reach Central. This is the only way to handle the legacy layout. README and the runtime warning both point to `--skip-unknown`. This is a data-quality risk, not exposure of individuals.

## Summary

The tool does what PROBLEM.md promises: `scan`, `push` and `csv` work end to end on modern and legacy Collect layouts, and the verdict stays `build`. No charter harms were found. It reads only local copies, talks only to the server the user names, keeps App User tokens out of the log, and does not decrypt encrypted forms. The main real-world bugs were in `push`. A single form the App User can't access (HTTP 403) stopped the whole upload. Re-copying a phone after finalizing a draft blocked that submission as a false conflict. A fixed 600 s request timeout would make large batches fail forever on slow links. Exit codes for `push` and `csv` also did not match the README, and batch sizing could go slightly over the server's limit. Each of these is fixed. Every fix has a regression test that failed before the change, except the timeout, for the reason given above. The README no longer points to release binaries that don't exist. fmt, clippy (`-D warnings`), tests and `cargo audit` all pass.

## Second review

- [fixed] data safety: submissions with media files that were not copied were uploaded without any warning in `push` or `--dry-run`, and logged as `created`. A later run that had the files skipped them, so the files never reached Central (src/lib.rs:319, src/push.rs:291). -> Push and dry-run now warn about each one. They are logged as `partial` and retried on the next run (Central adds attachments when the XML is byte-identical), and the exit code is 1. Test: `push_missing_attachment_is_retried_until_present`. The `push_with_basic_auth_and_options` test had encoded the old behavior and was updated.
- [fixed] credentials: an App User URL (a secret token) could only be given as `--server` on the command line, where `ps` and shell history show it (src/lib.rs:72). -> `ODK_SERVER` is read when `--server` is absent, and the README examples use it. Test: `server_url_can_come_from_environment` (in tests/env.rs, its own process because it sets an env var).
- [fixed] credentials: `--user` (Basic auth) was allowed over plain `http://`, which sends the password in clear text before Central refuses it (src/lib.rs:281). -> This is refused unless the host is loopback. Tests: `push_refuses_basic_auth_over_plain_http`, `loopback_hosts`.
- [unfixed] credentials: the password prompt still shows what you type. Turning echo off needs `libc`/termios (or a crate), not std. The prompt and the README say to use `ODK_PASSWORD` (set with `read -rs`) instead.
- [fixed] data safety: for encrypted submissions, every non-XML file in the folder was uploaded, including any plaintext media Collect failed to delete (src/instance.rs:345). -> Only files listed in the manifest (`submission.xml.enc` and the `<media><file>` entries) are attached. Test: `encrypted_submission_sends_only_manifest_files`.
- [fixed] correctness: `push --dry-run` returned 0 even with conflicts or unreadable submissions (src/lib.rs:344). Test: `dry_run_exit_code_flags_conflicts`.
- [fixed] correctness: a local file that could not be read was reported as a "network error", and the whole push stopped (src/push.rs:117). -> This is now a per-submission `unreadable` result: logged, not counted as done, and the upload continues. Test: `unreadable_files_are_not_network_errors`.
- [fixed] harm: CSV export wrote answers like `=HYPERLINK(...)` as-is, so spreadsheets would run them as formulas. -> Values starting with `= + @`, tab or CR get a leading `'`. Test: `defuses_spreadsheet_formulas`.
- [unfixed] honesty (expected): the `cargo install --git https://github.com/SignalForHumanity/odk-sneakernet` URL returns 404 until the repo is published.
